## 2. Process / world layout

```text
Manifest V3
│
├─ document_start, MAIN world
│   └─ scripts/inject.js
│       └─ lifecycle / visibility / focus compatibility shim
│
├─ document_start, isolated extension world
│   └─ scripts/content.js
│       ├─ page <-> extension message bridge
│       ├─ GA client/session ID storage helper
│       ├─ injects scripts/compat.js into page world
│       └─ injects scripts/main.js into page world
│
├─ page world
│   ├─ scripts/compat.js
│   │   ├─ early fetch compatibility/observation
│   │   ├─ ChatGPT/Sora user bootstrap observation
│   │   ├─ ChatGPT async conversation parsing
│   │   └─ ws.chatgpt.com WebSocket observer
│   │
│   └─ scripts/main.js
│       ├─ giant multi-provider runtime
│       ├─ ChatGPT adapter class `kZe`
│       ├─ task queue / rate limit / retry / persistence
│       ├─ passive conversation fetch parsing
│       ├─ active internal ChatGPT rescue calls
│       ├─ gallery/download plumbing
│       ├─ Autojourney membership / translation / optimization
│       └─ Google Analytics
│
└─ MV3 service worker
    └─ background.js
        ├─ downloadImage
        ├─ focusTab
        ├─ getInstallType
        └─ notification
```

Key architectural fact: **the long-running automation engine is page-resident, not service-worker-resident**. The service worker is intentionally thin.

## 4. `scripts/content.js` — bridge and bootstrap

Role: isolated-world bridge between page scripts and privileged extension APIs.

Approximate source locators in `content.js`:

- `function P()` message bridge: byte ~2,195
- `getGAClientId`: byte ~2,561
- `getGASessionId`: byte ~2,709
- inject `scripts/compat.js`: byte ~3,090
- inject `scripts/main.js`: byte ~3,173

Behavior:

1. identifies provider from hostname; ChatGPT source name becomes `AutoGPT`;
2. injects `compat.js` first;
3. injects `main.js` second;
4. installs `window.postMessage` bridge;
5. forwards page messages addressed to `background` through `chrome.runtime.sendMessage`;
6. serves two content-side helpers:
   - `getGAClientId`
   - `getGASessionId`.

GA storage details:

- `clientId`: generated with `crypto.randomUUID()`, stored in `chrome.storage.local`;
- session data: stored in `chrome.storage.session`;
- inactivity window: ~30 min.

This bridge is generic and easy to reproduce without product telemetry.

## 5. `background.js` — deliberately small

The background service worker does not own the generation queue.

Recognized message types include:

- `downloadImage`
  - calls `chrome.downloads.download`;
  - optionally saves associated text as `.txt`.
- `focusTab`
  - `chrome.tabs.update(tabId, {active:true})`;
  - `chrome.windows.update(windowId, {focused:true})`.
- `getInstallType`
  - uses `chrome.management.getSelf`.
- `notification`
  - uses `chrome.notifications.create`.

It also sets session storage access level to `TRUSTED_AND_UNTRUSTED_CONTEXTS`.

Reuse implication: nothing in this file is essential to prompt/upload/generation except optional focus/download/notification utilities.

## 6. `scripts/inject.js` — background-tab compatibility layer

This script runs in MAIN world at document start.

Important saved originals:

- `requestAnimationFrame`
- `cancelAnimationFrame`
- `setTimeout`
- `clearTimeout`
- `setInterval`
- `clearInterval`
- console methods
- original `document.visibilityState` copied to `document.hijackVisibilityState`.

Relevant source locators:

- visibilitychange interception: byte ~1,928
- pagehide interception: byte ~3,371
- `document.visibilityState` override: byte ~3,691
- `document.hidden` override: byte ~3,782
- `document.hasFocus = () => true`: byte ~3,857

For ChatGPT, the important visible behavior is:

- expose `document.visibilityState === "visible"`;
- expose `document.hidden === false`;
- expose `document.hasFocus() === true`;
- suppress/interpose selected page lifecycle events;
- preserve the real state separately as `document.hijackVisibilityState`.

There is also a helper in `main.js` (`f$`) that checks `document.hijackVisibilityState` and can dispatch a custom visibility event when AutoGPT wants to acknowledge a genuinely hidden page.

Reuse interpretation:

- do not assume this is pointless spoofing;
- it is specifically a hidden/background-page compatibility tool;
- VoiceBridge 0.2.6 independently demonstrated that Vivaldi can leave hidden ChatGPT tabs with incomplete DOM rendering;
- keep this mechanism as an optional compatibility module for multi-worker background execution.

## 10. Image-mode selection

Method:

`switchGPTGenerateType("image")`

Sequence:

1. inspect current composer inline selection pill;
2. if already image mode, return;
3. find `#composer-plus-btn` inside the GPT editor container;
4. `.click()`;
5. wait ~500 ms;
6. inspect menu items under:
   - `.popover .__menu-item`
   - `div[data-radix-popper-content-wrapper] .__menu-item`;
7. classify menu item through `getGPTEditorGenerateTypeByButton`;
8. click the item classified as image;
9. wait another ~500 ms.

Current image mode detection inspects:

- `#prompt-textarea [data-inline-selection-pill]`
- pill attributes:
  - `data-id`
  - `data-system-hint-type`
- visual/menu classification fallback.

Reuse: strong direct candidate if the Custom GPT worker requires explicit image mode selection.

## 11. Canonical/file upload — exact AutoGPT path

ChatGPT entry:

`gptUploadImages(files)`

It calls shared:

`simulateUpload({ input, files, afterUpload })`

### Input resolver

The resolver is re-evaluated at upload time:

`getGPTEditorContainer()?.querySelector('input[type="file"]')`

That re-resolution matters because React may remount the composer/input.

### Shared `simulateUpload`

Exact high-level sequence:

```text
resolve/convert files
    ↓
new DataTransfer()
    ↓
dataTransfer.items.add(file) for each file
    ↓
resolve CURRENT input element
    ↓
input.files = dataTransfer.files
    ↓
dispatch new Event("change", {bubbles:true})
    ↓
afterUpload()
```

Important: **no preceding file-input `input` event** in this path.

If `queue` mode is used by another provider it sends files one by one with ~500 ms spacing; the ordinary ChatGPT path uses the group directly.

### ChatGPT upload completion predicate

`gptUploadImages` does not require the filename text to become visible.

It waits with roughly:

- polling interval: 2,000 ms
- timeout: 90,000 ms.

Ready predicate is approximately:

1. no `circle` remains inside the GPT editor container; and
2. `#composer-submit-button` is either absent, or:
   - not disabled; and
   - its `data-testid` is not `stop-button`.

There is also `uploadImageReject`, which can reject the wait early when the runtime detects an explicit upload failure.

**This predicate is the preferred reference for Worker Fanout.** `input.files` alone is too weak; visible filename alone is stricter than AutoGPT and not its actual success criterion.

## 12. Prompt insertion — ChatGPT-specific paste path

Target used by `gptImagine`:

`document.querySelector("#prompt-textarea p")`

Method:

`setGPTPromptEditorValue(editor, text, keepInlineSelection=true)`

Sequence:

1. `editor.click()`;
2. `editor.focus()`;
3. wait ~50 ms;
4. obtain `window.getSelection()`;
5. create `Range`;
6. if preserving the image-mode inline pill:
   - find `[data-inline-selection-pill]`;
   - set range start after the pill;
   - set end at the editor's final child;
7. otherwise select the editor contents;
8. replace active selection;
9. wait ~100 ms;
10. create `ClipboardEvent("paste", {bubbles:true, cancelable:true})`;
11. create a `DataTransfer`;
12. `dataTransfer.setData("text/plain", text)`;
13. define event `.clipboardData` as that DataTransfer;
14. dispatch the paste event to the editor.

This is **not** a simple `textContent = ...` implementation and is more ChatGPT-specific than the generic contenteditable code used in early Worker Fanout versions.

Reuse: strong direct candidate.

## 14. Shared submit sequencing: `simulateImagine`

Signature includes hooks such as:

- `value`
- `textarea`
- `nonce`
- `timeout`
- `sendTimeout`
- `resetPreciseTimeout`
- `onTrigger`
- `onSetValue`
- `onCheckSend`
- `beforeSend`
- `afterSend`
- `onSend`
- `beforeTimeout`
- `onTimeout`.

Important sequence:

```text
nonce = supplied nonce or Gi()
    ↓
set editor value (provider hook or generic path)
    ↓
optional onCheckSend()
    ↓
~50 ms scheduled send phase
    ↓
VN(nonce, describe metadata)   // publish active precise nonce
    ↓
beforeSend(nonce)
    ↓
onSend(nonce)                // register/correlate listeners
    ↓
trigger actual submit
    ↓
afterSend(nonce)
    ↓
~500 ms: Ya(nonce)            // clear active precise nonce if same
    ↓

```

For ChatGPT `gptImagine`, total send/result timeout is set to ~60 s; precise reset is ~30 s.

### Default trigger: synthetic Enter

Shared helper:

`async function nf(element, options)` at main.js byte ~1,769,205.

It dispatches:

1. `KeyboardEvent("keydown")` with Enter/keyCode 13;
2. waits ~100 ms;
3. `KeyboardEvent("keyup")` with Enter/keyCode 13.

No Shift; optional Ctrl/Meta can be supplied by other providers.

Reusable principle: **observer/listener correlation is armed before activation**. Translation Loop's runToken/stale-result control complements this well.

## 15. Nonce / precise-send state

Shared global state:

- `YN`: current active nonce
- `vue`: optional metadata.

Helpers:

- `VN(nonce, metadata)` → set current precise nonce/metadata
- `Ia()` → return active nonce
- `RXe()` → return metadata
- `Ya(nonce)` → clear only if supplied nonce still matches.

This is one of the mechanisms preventing unrelated/old asynchronous events from being credited to a new task.

Translation Loop's `runToken` should remain the higher-level orchestration token; AutoGPT's per-send nonce can remain a lower-level submission token.

## 16. Main ChatGPT POST observer and positive commit evidence

The large runtime has its own page-world fetch observation in addition to the early `compat.js` wrapper.

Relevant ChatGPT routes include:

- `/backend-api/conversation`
- `/backend-api/f/conversation`.

For ChatGPT conversation POSTs the runtime can:

1. read the outgoing request body;
2. identify prompt/message metadata;
3. observe/copy `Authorization` when present;
4. execute the original page fetch;
5. clone a successful response;
6. parse the clone without consuming the page's response.

The stream parser is:

`async function ytt(reader, context)` at main.js byte ~2,445,214.

It recognizes stream records including:

- normal `add`/`append`/`patch` forms;
- `stream_handoff`;
- `conversation_async_status`;
- `metadata.async_source`;
- `metadata.ghostrider.status === "intermediate"`;
- `metadata.image_gen_async`;
- `turn_exchange_id`;
- inline `image_asset_pointer`.

### Commit evidence

As soon as a conversation ID is established, the parser calls the path that emits:

`gpt-imagine`

through helper `SZe(...)`.

That event is used as positive evidence that the intended send was accepted into a ChatGPT conversation.

Important design split:

- passive response observation can be used for commit evidence;
- Bearer storage is separate;
- active private endpoint calls are separate.

MYGPT can adopt the first without automatically adopting the latter two.

## 18. Async-generation detection and rescue

The stream parser marks a conversation as async when it sees signals such as:

- `conversation_async_status` not complete;
- `metadata.async_source`;
- `ghostrider.status === "intermediate"`;
- `metadata.image_gen_async`;
- `stream_handoff`.

It records exchange/message correlations in global maps such as:

- `window.gptTurnUserMap`
- `window.gptExchangeIdMap`
- `window.gptDescribeMsgIds`.

If there is no inline image result, helper `JU(...)` registers rescue state.

### Active internal conversation probe schedule

Constant:

```text
vtt = [
  60s,
  120s,
  180s,
  240s,
  300s,
  360s,
  420s,
  480s,
  540s,
  600s
]
```

At each scheduled point, unless the conversation/message is already marked settled, it calls:

`xXe(conversationId)`

which performs:

`GET https://chatgpt.com/backend-api/conversation/{conversationId}`

with stored `Authorization`.

This is **result recovery**, not prompt resubmission.

The passive `ws.chatgpt.com` observer in `compat.js` runs alongside this and can satisfy the rescue earlier.

## 19. Internal file-download metadata resolution

Helper:

`wXe({fileId, conversationId})`

calls:

`https://chatgpt.com/backend-api/files/download/{fileId}?conversation_id={conversationId}&download_intent=false&inline=false`

with stored `Authorization`.

The response is observed and a `download_url` can be associated with the file asset.

`rde(...)` uses this to convert ChatGPT asset pointers into usable output URLs before emitting the final created event.

Interpretation:

- useful for automatic output extraction/download;
- not required for canonical attachment, prompt insertion, send activation or positive conversation commit evidence.

## 20. Rate-limit / backpressure subsystem

ChatGPT-specific detector:

`ode(text, debug)` at main.js byte ~2,275,131.

It calls a common parser using configured word lists:

- `gptRateLimitWords`
- `gptQuotaLimitWords`.

When a limit is detected it emits/logs the condition and calls the common limiter (`vm(...)`).

Observed policy from the deep analysis:

- ordinary rate-limit fallback wait: roughly 5 min if no explicit time is parsed;
- ordinary wait capped around ~30 min;
- quota-style fallback roughly ~30 min + small safety buffer;
- long quota wait cap around ~6 h.

The runtime stores a rate-limit expiry and blocks queue progress until the window passes.

Product defaults include:

- `autoRetry: false`
- `autoRetryTimes: 1`.

Therefore distinguish:

1. **backpressure / wait** — useful and safe concept;
2. **result polling** — observation of already-submitted work;
3. **prompt retry** — optional, bounded and off by default.

Do not conflate the three.

## 22. Product-only external systems

These are **not core ChatGPT automation** and are the primary stripping targets for an internal MYGPT clone.

### Google Analytics

Endpoint:

`https://www.google-analytics.com/mp/collect`

Known helper behavior:

- obtains/stores client ID and session ID;
- adds `discord_user_email` from the product user-email getter;
- adds membership state;
- call-site analysis found 108 analytics helper calls;
- at least several `send_button_clicked` calls include an actual `prompt` property;
- page-view events include active URL.

Strip completely.

### Membership / entitlement

Known service origins:

- `https://apijourney.autojourney.top`
- `https://apijourney.autojourney.ai`
- `https://apijourney.zeabur.app`
- `https://apijourney.kingback.app`

Path:

`/api/checkAuth/isMember`

Uses account/provider/extension/time-zone style metadata and verifies returned signed entitlement data.

Strip completely.

### Prompt translation / optimization

Paths include:

- `/api/translate/prompts`
- `/api/midjourney/prompts`

They can send full prompt text and account metadata to Autojourney services.

Strip completely for MYGPT.

### imgbb helper

Endpoint:

`https://api.imgbb.com/1/upload?...`

Payload includes image and email.

Important nuance: **normal ChatGPT `gptUploadImages` does not use this helper**. It uses ChatGPT's own file input.

Strip the helper and keep ChatGPT local File/DataTransfer upload.

## 28. Current reuse conclusion

The useful mental model is:

**AutoGPT 0.0.71 = visible ChatGPT automation + layered observation/recovery + unrelated commercial product shell.**

The target for MYGPT is not a clean-room imitation of only the visible controls. It is a **stripped ChatGPT clone** of the mature mechanisms, with the product shell removed, then combined with Translation Loop and VoiceBridge.

Primary strip targets:

- analytics;
- membership;
- external prompt/account services;
- unrelated providers/product UI.

Primary retain targets:

- ChatGPT adapter;
- upload readiness;
- paste insertion;
- nonce/submit sequencing;
- passive fetch/WS observation;
- useful backpressure;
- optional hidden-tab compatibility.

This reference supersedes the earlier simplistic rule that only AutoGPT's visible UI primitives should be reused.
