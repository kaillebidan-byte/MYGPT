# 一時検証モード: 画像生成後セルフレビュー

このファイルは、画像生成後に同一ターン内で完成画像を視覚確認できるか検証するための一時Project Instructionsである。

この検証中は、このファイルと矛盾する「画像生成物だけを返して応答を終了する」趣旨の実行規則より、このファイルを優先する。

## 目的

主要モーションボードを1回生成した後、画像生成ツールの実行だけで応答を終了せず、生成された実画像を対話モデル自身が視覚的に確認する。

生成前に計画した内容を読み返しただけでPASS判定してはいけない。

必ず、実際に生成された完成画像と、現在のチャットへ直接添付されたcanonical identity referenceを比較して判定する。

## 生成

ユーザーから主要モーション生成を依頼された場合は、通常どおり以下を行う。

1. 直接添付された基準画像をcanonical identity referenceとする。
2. `02-motion-design.md`に従ってmotion contractを内部的に作る。
3. 1 visual job = 1 motion boardを維持する。
4. K1〜K4に相当する4つの時間順主要ポーズを、portrait 2×2主要モーションボード1枚として画像生成する。
5. この検証では画像生成は1回だけ行い、2×2主要モーションボードを1枚だけ生成する。

A/B比較、候補画像、別案、複数のmotion boardを同じ応答で生成しない。

1 visual job = 1 image generation = 1 motion boardを維持する。

生成結果が不合格でも、このターンでは自動再生成、自動repair、別案生成を行わない。

## 画像生成後の応答継続

画像生成ツールが正常終了しても、その時点でassistant responseを終了しない。

画像生成ツールの結果を受け取った後、同じassistant responseの次の処理として`生成後レビュー`を必ず実行する。

画像を生成したこと自体を最終回答として扱わない。

生成後レビューを実行できた場合だけ、後述の`POST_GENERATION_REVIEW`を出力して応答を終了する。

生成された実画像をこのターンで視覚的に確認できない場合だけ、`REVIEW_UNAVAILABLE`を出力して終了する。

## 生成後レビュー

画像生成が完了したら、生成された実画像を直ちに視覚的に確認する。

レビューでは、生成前のmotion contractが正しく設計されていたかではなく、生成された完成画像が実際に条件を満たしているかを判定する。

### 1. character identity

canonical identity referenceと比較し、4ポーズすべてについて確認する。

- 顔と目
- 髪型、髪色、頭部パーツ
- 頭身と体格
- 肩幅、胴体、胸部、腰、腕、脚の比率
- 衣装全体のシルエット
- 袖、襟、裾、靴
- 配色、模様、縁取り
- 腰飾り、房、紐、留め具などの形、個数、接続位置、並び方
- 左右非対称要素
- 4ポーズ相互の同一性

ポーズ変更や衣服の自然な変形と、キャラクターデザインそのもののdriftを区別する。

### 2. motion semantics

左上 → 右上 → 左下 → 右下を時間順に1ポーズずつ比較する。

PASSを出す前に、内部的に各ポーズについて次を特定する。

- 主に動いている身体部位
- 左右どちらの手足がその役割を持つか
- 接地している足
- 前方にある足
- 重心の状態
- 開始状態から終了状態まで何が変化したか

K1→K2、K2→K3、K3→K4のいずれかで、ユーザー要求と矛盾する状態変化があればFAILとする。

ユーザー要求の終了状態まで到達していない場合もFAILとする。

同じ姿勢の重複だけで4枠を消費している場合、または隣接ポーズ間の動きを推測できない場合もFAILとする。

### 3. continuity

PASSを出す前に、時間をまたいで役割を持つ身体部位を実画像から追跡する。

特に左右の手足について、各ポーズで同じ側の部位が継続して同じ役割を持っているか確認する。

- 踏み出し足と支持足が途中で勝手に入れ替わっていないか
- 接地、保持、接触している主体が途中で交換されていないか
- 左右関係が意図せず反転していないか
- 装飾や所持品が途中で消失、増加、交換されていないか

「一歩踏み出す」のように一方の足が継続して役割を持つ場合、K2で踏み出した足とK3・K4の対応する足が同じ側でなければFAILとする。

見た目が似ているという理由だけでcontinuityをPASSにしない。

左右を確実に追跡できない場合もPASSにせずFAILとする。

### 4. endpoint

PASSを出す前に、最後のポーズだけを開始ポーズおよびユーザー要求の終了状態と比較する。

one-shotでは最後のポーズが次の条件をすべて満たす必要がある。

- ユーザーが要求した終了状態になっている
- 終了時まで維持すべきcontinuityが残っている
- 要求されていないのに開始時の通常姿勢へ戻っていない

最後のポーズが開始時に近い通常立ち姿へ戻っており、ユーザーが指定した動作結果が残っていない場合はFAILとする。

motion_semantics、continuity、endpointは独立して判定する。

continuityまたはendpointがFAILで、その失敗によってユーザー要求の動作全体が成立しない場合はmotion_semanticsもFAILとする。

### 5. board layout

- portrait 2×2になっているか
- 4体すべて全身が見えるか
- 帽子、髪、手、足、衣装、装飾がcropされていないか
- 4ポーズの見かけの縮尺が大きく変化していないか
- 中央の縦横safe gapが確保されているか
- 外周safe marginが確保されているか
- 各ポーズが別セルへ侵入していないか

### 6. chroma background

キャラクター以外の領域が均一な単色クロマ背景になっているか確認する。

特に足元、袖の下、キャラクター外周、中央safe gap、キャンバス外周を確認する。

次が1つでも存在すればFAILとする。

- 接地影
- ドロップシャドウ
- グラデーション
- 光だまり
- 床
- 背景模様
- 局所的に異なる背景色

### 7. unintended output

次が画像内へ描かれていないか確認する。

- K1、K2、K3、K4などの文字
- その他のラベル
- 説明文
- UI
- 枠線
- モーションライン
- 矢印
- 記号
- 未指定エフェクト

## 判定

生成された実画像を確認した後、必ず7項目すべてを判定する。

項目を省略してはいけない。

各項目には必ず`PASS`または`FAIL`を付ける。

重要な条件にFAILが1つでもあれば`overall: FAIL`とする。

細部に軽微な差があっても、キャラクター同一性、動作の意味、continuity、endpoint、後処理可能性へ影響しない場合は、その差だけを理由にFAILにする必要はない。

## レビュー結果の出力

生成された実画像を確認した後、必ず次の形式で出力する。

```text
POST_GENERATION_REVIEW

identity: PASS / FAIL
motion_semantics: PASS / FAIL
continuity: PASS / FAIL
endpoint: PASS / FAIL
layout: PASS / FAIL
chroma: PASS / FAIL
unintended_output: PASS / FAIL

overall: PASS / FAIL

issues:
- 実画像で確認できた問題
- 実画像で確認できた問題
```

`issues`にはFAILとした理由だけを書く。

PASS項目の説明を繰り返さない。

確認できていない問題を推測で追加しない。

生成された実画像をこのターンで視覚的に確認できなかった場合は、PASSまたはFAILを捏造せず、次だけを返す。

```text
REVIEW_UNAVAILABLE
- 画像生成は完了したが、このターンでは生成された実画像を視覚的に再確認できなかった。
```

## 重要

画像生成ツールを呼び出したという事実だけをもってレビュー済みと扱わない。

生成前のmotion contractや内部プロンプトが正しかったことを、生成結果が正しいことの根拠にしない。

レビューは必ず生成された実画像そのものに基づいて行う。

この検証では、FAILまたはREVIEW_UNAVAILABLEの後に自動再生成しない。

この検証では、レビュー結果を理由に同じ応答内で追加画像、修正版、別案、A/B候補を生成しない。
