# Keypose Board Specification

この資料は、画像生成段階の1枚の2×2モーションボードだけを定義する。

最終フレーム画像、最終スプライトシート、アトラスのピクセル寸法や後処理方法は定義しない。

## 基本構成

1枚の画像に1動作だけを描く。

4つの時間順キーポーズを2列×2行へ配置する。

- 左上: K1
- 右上: K2
- 左下: K3
- 右下: K4

K1〜K4は4枚の別画像ではなく、1つのmotion board内の4状態とする。

モーション依頼1件につき、この2×2ボードを1枚だけ生成する。横4枚版、別案、追加ボード、個別K1〜K4を同時に生成しない。

キャンバス上にグリッド線、枠、K1〜K4ラベルは描かない。位置関係だけを2×2として扱う。

## canonical identity reference

4ポーズすべてについて、現在のチャットへ直接添付された同じ基準キャラクター画像を視覚的正本とする。

過去の生成画像、別チャットの画像、Project Sources内の画像をキャラクター正本へ切り替えない。

1枚のボード内で4ポーズを別々のキャラクターデザインとして再解釈しない。

## キャンバス比率

モーション用2×2ボードは正方形を既定にしない。

各象限が縦長になるportraitキャンバスを使う。既定の目安は幅:高さ = 2:3で、生成機能が対応する場合は1024 × 1536 px相当を選ぶ。

1024 × 1536 pxの2×2なら、各象限は論理上512 × 768 px相当になる。

生成機能が厳密なピクセル値を指定できない場合も、利用可能なportrait比率のうち2:3に近いものを選び、正方形キャンバスへ4体を詰め込まない。

## layout guide

`project/sources/layout-guides/four-pose-portrait.png`が利用可能な場合は、4スロット、中央safe gap、外周safe marginの幾何だけを参照する。

layout guideはキャラクター同一性や画風の参照画像ではない。

ガイド内の枠、K1〜K4ラベル、線、灰色領域、背景色を最終画像へ描き写さない。

layout guideを画像生成側が参照できない場合でも、ユーザーへ追加画像を要求せず、この文書の幾何条件で生成する。

## 各ポーズ

各象限には同じキャラクターを1体だけ描く。

4体は同じ衣装、顔、髪、配色、模様、装飾、体格、画風、カメラ角度、見かけの縮尺を共有する。

4ポーズすべてを、頭頂から靴底まで完全に見える全身像として描く。半身、バストアップ、腰から下の省略は禁止する。

帽子、髪、耳、角、上げた手、足、衣服、尾、翼、装飾、所持品まで割り当て象限の内部へ完全に収める。

全身が象限へ収まらない場合は、身体の一部を切るのではなく、4ポーズを同じ倍率で小さくして全身と付随物を収める。特定のポーズだけ別倍率にしない。

各キャラクターを象限いっぱいまで拡大しない。全身の周囲に目で明確に確認できるnegative spaceを残す。

ポーズによって必要な身体位置の変化は許容するが、キャラクターの頭身、胴体形状、胸部を含む体格そのものを変えない。

4体を互いに重ねない。

## 中央safe gapと外周余白

2×2の中央を通る縦方向と横方向の仮想境界には、キャンバス全体を横断する連続した空き帯を必ず残す。

帽子、髪、耳、角、手、足、衣服、尾、翼、装飾、所持品を中央の空き帯へ侵入させない。

上段2ポーズは横方向中央線より完全に上、下段2ポーズは完全に下、左列2ポーズは縦方向中央線より完全に左、右列2ポーズは完全に右へ収める。

各ポーズは割り当てられた象限の内部だけに存在し、中央線をまたがない。収まらない場合はcropせず、4ポーズすべてを同じ倍率でさらに小さくする。

キャンバス外周にも上下左右すべてで目で明確に確認できる余白を残す。キャラクター本体、髪、帽子、手足、衣装、装飾、所持品をキャンバス端へ接触させない。

## chroma-key background

画像生成段階の背景は真の透明ではなく、ボード全体で均一な単色クロマキーとする。

既定候補は高彩度magenta。キャラクター本体の配色と衝突する場合はcyan、blue、greenなど、キャラクター本体から十分に離れた高彩度色を1色選ぶ。

4象限、中央safe gap、外周余白のすべてで同じクロマ色を使う。

床、接地面、接地影、ドロップシャドウ、風景、背景模様、グラデーション、光だまりを描かない。

画像生成後に`audit/scripts/remove_chroma_key.py`でクロマ背景をalphaへ変換する。

## 描かないもの

- グリッド
- 枠
- 番号
- K1などのラベル
- 矢印
- 説明文
- UI
- チェック柄の透過表現
- 床や接地影
- モーションライン
- キラキラ、星、音符、汗などの感情・動作記号
- 粒子、発光、軌跡などの未指定エフェクト

ユーザーが明示的に要求していない演出要素を、動作の説明目的で追加しない。

## 時間順

4ポーズの意味は`02-motion-design.md`で決める。

この資料では、K1 → K2 → K3 → K4が時間順であることだけを固定する。

## audit入力

本番の後処理は次の順で行う。

```text
raw chroma 2x2 board
  -> remove_chroma_key.py
  -> transparent 2x2 board
  -> build_motion_strip.py
  -> normalized transparent motion strip
```

`audit/scripts/build_motion_strip.py`へ渡す前に、`remove_chroma_key.py`で背景をalphaへ変換する。

`build_motion_strip.py`は2×2ボードを機械的に分割し、各セルのalpha bbox、端接触、共通倍率を処理する。

4枚個別画像入力は過去実験との互換用としてコードに残してよいが、新しいChatGPT Projectの本番画像生成経路では使わない。

## 8フレーム化

最終8フレームが必要でも、最初のvisual jobへ8体を直接描かない。

まず4つの主要キーポーズをこの2×2ボード1枚として生成する。

必要な中割り4ポーズは、主要キーポーズとは別の後続visual jobとして2×2ボード1枚を生成する。同一応答内で主要ボードと中割りボードを自動的に連続生成しない。

最終的な切り出し、倍率統一、位置合わせ、フレーム配置は画像生成後の処理へ任せる。

## 生成段階の合格条件

- 画像生成結果が1枚だけである
- その1枚に4ポーズだけ存在する
- ボード全体がportraitで、各象限が縦長である
- 4象限に1ポーズずつある
- K1 → K2 → K3 → K4の順に動作が読める
- 4ポーズが同じキャラクターとして読める
- 顔、髪、衣装、配色、模様、装飾、体格が共通している
- カメラ角度と見かけの縮尺が揃っている
- 4ポーズすべてで頭頂から靴底まで見える
- 全身と付随物が切れていない
- 各キャラクターの周囲に明確なnegative spaceがある
- 中央の縦横境界を横断する連続した空き帯がある
- どのポーズも中央線をまたいでいない
- キャンバス外周の上下左右すべてに明確な余白がある
- キャラクターや付随物がキャンバス端へ接触していない
- 背景が均一な単色クロマキーである
- 床、接地影、ドロップシャドウがない
- 枠、番号、文字、UIがない
- 未指定のモーションライン、記号、粒子、発光などのエフェクトがない
